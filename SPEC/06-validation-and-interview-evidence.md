# Validation and Interview Evidence

## Engineering checks

Run domain tests for transitions, event replay, idempotency and handoff depth; provider tests for timeout/cancel/resume and structured output; sandbox tests for path traversal, symlinks, shell allowlists, secret redaction and cross-project isolation; then run clean-room setup, Web build and Electron packaging when the registry is available.

## Reality checks

Use three non-sensitive tasks from the owner's real workflow. Compare elapsed time, manual整理 steps, rework, traceability, interruption recovery and willingness to use again. Fixture and model self-evaluation are not user evidence.

## Interview proof

Keep separate packs: runnable demo, personal mastery notes and interviewer-facing architecture/evidence. The demo must show one Run, one structured handoff, one approval, one provider receipt and one Artifact. Claims must point to a file, test or real-use record.
