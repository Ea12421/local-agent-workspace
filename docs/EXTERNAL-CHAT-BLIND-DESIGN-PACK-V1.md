## 产品目标

我想做一个本地优先的 Agent Workspace / Project Bot OS。

用户可以按项目创建和管理 Bot。每个 Bot 有：

- 明确职责；
- 输入和输出格式；
- 可使用的工具；
- 权限范围；
- 可选模型或执行 Provider；
- Memory 策略；
- 审批规则；
- 失败和停止条件。

首个使用场景是 Product Builder：

```text
一个产品想法
→ 澄清未知信息
→ 规划任务
→ 做研究
→ 形成产品定义
→ 评估技术方案
→ 制定评测方案
→ 生成可执行计划
```

## 真实问题

当前工作通常是：

```text
长 Chat 对话
→ 人工复制和整理
→ 自己判断方案
→ 再交给代码执行工具
→ 中断后上下文丢失
→ 很难知道谁做了什么、依据是什么、结果是否可靠
```

这个系统要解决：

1. 长任务状态可追踪；
2. 中断、限额、上下文压缩后可以恢复；
3. Bot/Workflow 的职责和交接清楚；
4. 工具真正可调用，但不能越权；
5. 模型或 Provider 可以更换；
6. 能观察成本、延迟、重试和失败；
7. 结果可追溯到来源、Run、工具和审批；
8. 无 API Key 时仍能进行演示和工程验证。

## 使用条件

- 首个用户是单人 AI Builder / AI 产品经理 / 独立开发者；
- 优先本地运行；
- 需要 Web 启动方式和 macOS 桌面方式；
- 需要能从 GitHub 下载后复现；
- 需要支持一个订阅型执行通道和至少一个 API 型模型通道；
- 订阅额度和 API 额度必须严格区分；
- 不默认上传项目内容；
- 默认权限应从只读开始；
- 外发、删除、敏感路径、发布、支付、读取凭据必须逐次审批；
- 无人工确认时不能自动创建无限 Bot、自动提升权限或自动发布；
- 不能把模型自评当作产品效果证明。

## 必须考虑的长任务问题

### 成本

长任务可能重复发送：

- 系统规则；
- Bot 职责；
- 工具定义；
- 项目固定背景；
- 历史摘要；
- 最近事件；
- 工具结果。

请设计成本控制，但必须区分：

- 影响正确性的机制；
- 只影响速度的机制；
- 只影响费用的机制；
- 需要 Provider 支持才能成立的机制。

### Prompt Cache

请回答：

- 什么内容适合缓存；
- 如何形成 cache key；
- 项目状态、权限、工具 Schema 改变时如何失效；
- Provider 不返回命中数据时如何保持诚实；
- 缓存是否应该成为必需能力；
- 如何记录命中、未命中、写入、缓存 token 和估算值；
- 如何避免把敏感内容泄漏到缓存或日志。

### 工具调用

请设计完整闭环：

```text
模型提出工具调用
→ 参数校验
→ 权限检查
→ 必要时审批
→ 工具执行
→ 结果记录
→ 返回模型
→ 继续任务
```

必须考虑：

- 工具 Schema；
- callId 幂等；
- 越权拒绝；
- 路径穿越和符号链接；
- Shell 风险；
- 超时；
- 取消；
- 重试；
- 审批拒绝；
- 最大循环深度；
- 工具结果过大时的压缩；
- 中断恢复后避免重复执行。

### Provider 切换

请设计一个能区分以下情况的体系：

- 订阅型执行 Agent；
- API 型模型 Provider；
- OpenAI-compatible API；
- 本地模型；
- Fixture/Mock。

请特别说明：

- 哪些能力可以共用；
- 哪些能力必须由 Adapter 单独实现；
- streaming、tool calling、structured output、reasoning、usage、cache 和 resume 如何探测；
- 为什么“请求格式兼容”不代表“行为兼容”；
- 认证、计费和额度如何分开记录。
