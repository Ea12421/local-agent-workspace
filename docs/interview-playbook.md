# Interview Playbook

Explain the project as a traceability and control problem: one strong model can generate text, but a product workflow needs ownership, schemas, approvals, recovery and evidence. Show the state transition, the HandoffEnvelope and a receipt. Be explicit about what is fixture, what is DeepSeek, what is Codex execution, and what has not yet passed real-user validation.

When asked why multi-Bot, use the ablation rule in `SPEC/04`: keep it only when fixed tasks show less manual rework or a meaningful quality lift within the cost/latency bound. When asked about security, describe the three permission tiers and the always-approval actions rather than claiming the local computer is a security boundary.
