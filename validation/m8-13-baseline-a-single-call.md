# 目标

为 `personal-knowledge-mcp-mvp` 制定一份可重复的离线验证报告计划，验证以下范围：

- 仅使用 `fixtures/notes/` 中的三份 synthetic Markdown。
- 通过只读 MCP 工具执行搜索和按 `note_id` 读取。
- 结果包含可核对来源。
- 保持 fixture-only、localhost-only、只读。
- 不接入真实知识库、不启动公网服务、不修改候选项目。

# 已知事实

- 项目目标是验证 ChatGPT 可通过官方 Node MCP SDK 的只读工具检索虚拟 Markdown，并返回可核对来源。
- 当前实现只搜索 `fixtures/notes/` 中的三份 synthetic Markdown。
- 搜索先返回服务端生成的 16 位 `note_id`，再按 `note_id` 读取正文。
- 工具不接受任意文件路径。
- 2026-07-17 的项目记录包含：
  - 本地 npm test 的 9 项机械检查 PASS。
  - 一次普通 ChatGPT Web 的 `search_knowledge` / `read_knowledge` 记录。
- 上述结果是历史记录，不是本轮重新复核结果。
- MCP 服务和临时 HTTPS tunnel 当前均已停止。
- 当前没有可访问后端。
- 项目只允许使用 `fixtures/notes/`。
- 不读取真实 Obsidian、其他项目目录、用户目录、账号数据或 secret。
- 不写入、修改、删除、上传资料。
- 默认只监听 `127.0.0.1`。
- 没有生产鉴权，不得作为长期公网服务。
- 尚未证明：
  - 真实资料接入。
  - 生产鉴权。
  - 长期 tunnel。
  - GPT-Live 直接调用。
  - 真实用户效果。

# 建议步骤

## 1. 冻结离线验证范围

明确本轮报告只覆盖：

- 三份 synthetic Markdown。
- 搜索工具。
- `note_id` 读取工具。
- 来源可核对性。
- 只读和路径边界。

不纳入真实知识库、真实用户资料、生产鉴权、公网部署、长期 tunnel 或 GPT-Live。

## 2. 建立固定验证输入集

为三份 fixture 记录固定的人工可核对信息：

- 文件对应的稳定语义主题。
- 可用于命中的关键词。
- 预期搜索结果。
- 每个结果对应的 `note_id`。
- 读取后应出现的正文和来源信息。

如果项目没有现成的固定输入表，则该表的具体内容为未知，需要在不修改候选项目的前提下，作为报告外部的验证记录维护。

## 3. 重新执行本地机械检查

在本地、仅针对候选项目允许的 fixtures 范围，重新执行已有的 9 项机械检查。

报告中应区分：

- 本轮重新执行的结果。
- 2026-07-17 的历史结果。
- 未执行或无法执行的检查。

不得把历史 PASS 写成本轮 PASS。

## 4. 验证搜索—读取闭环

针对固定关键词验证：

1. 搜索是否只返回 `fixtures/notes/` 范围内的结果。
2. 每个结果是否返回服务端生成的 16 位 `note_id`。
3. 是否可以仅凭 `note_id` 读取对应正文。
4. 读取结果是否包含可核对来源。
5. 是否不存在任意文件路径读取能力。

## 5. 验证只读与路径边界

使用不改变数据的边界检查，确认：

- 不接受任意文件路径作为读取目标。
- 不读取 fixtures 目录之外的内容。
- 不写入、修改或删除 fixture。
- 不上传资料。
- 不保存请求正文。
- 不接入真实 Obsidian、用户目录、其他项目目录或 secret。

如果某项无法在当前没有运行后端的状态下重新验证，应标记为“本轮未验证”，不能推断为已满足。

## 6. 生成离线验证报告

报告至少包含：

- 验证日期。
- 验证范围与明确排除项。
- fixture 清单。
- 测试输入。
- 预期结果。
- 实际结果。
- PASS / FAIL / NOT VERIFIED。
- 来源核对结果。
- 历史记录与本轮结果的区分。
- 环境限制：当前没有可访问后端。
- 未证明事项。
- 停止条件和风险。

报告不得包含真实资料、请求正文、账号数据、secret 或 fixtures 之外的文件内容。

## 7. 保留运行边界

如后续需要临时启动本地验证环境，也必须同时满足：

- 仅监听 `127.0.0.1`。
- 仅用于离线或本地验证。
- 不启动公网服务。
- 不建立长期 tunnel。
- 不接入真实知识库。
- 不扩大文件访问范围。
- 验证结束后停止服务。

# 每步验收

| 步骤 | 验收标准 |
|---|---|
| 冻结范围 | 报告明确写出 fixture-only、localhost-only、只读，以及所有排除项 |
| 固定输入集 | 三份 synthetic Markdown 均有可重复的关键词、预期结果和来源核对方式 |
| 机械检查 | 明确区分本轮结果与 2026-07-17 历史结果 |
| 搜索—读取闭环 | 搜索结果可通过 16 位 `note_id` 读取对应正文，并返回可核对来源 |
| 路径边界 | 无法通过任意文件路径读取 fixtures 之外的内容 |
| 只读边界 | 没有写入、修改、删除、上传或请求正文持久化行为 |
| 报告产出 | 报告可由另一位执行者根据固定输入重复验证 |
| 运行边界 | 未启动公网服务；如启动本地服务，仅监听 `127.0.0.1`，结束后停止 |

# 未知项

- 当前项目是否仍能在本地成功运行既有 9 项机械检查。
- 当前三份 fixture 的具体文件名、关键词和预期命中关系。
- 当前实现是否仍与 2026-07-17 的历史记录一致。
- 16 位 `note_id` 是否在每次运行中稳定，还是仅在单次运行期间有效。
- 搜索结果中的来源字段具体格式。
- 当前是否存在现成的固定验证输入表。
- 当前是否能在不修改候选项目的情况下启动本地验证环境。
- 当前 MCP 工具是否能被普通 ChatGPT Web 重新调用。
- GPT-Live 直接调用是否可行。
- 真实资料接入、生产鉴权、长期 tunnel 和真实用户效果均未知且不属于本轮验证范围。

# 停止条件

出现以下任一情况，应停止本轮验证并记录原因：

- 需要读取 `fixtures/notes/` 之外的文件。
- 需要访问真实 Obsidian、用户目录、其他项目目录、账号数据或 secret。
- 需要写入、修改、删除或上传资料。
- 需要保存请求正文。
- 需要监听非 `127.0.0.1` 地址。
- 需要启动公网服务或长期 tunnel。
- 需要接入真实知识库。
- 无法区分本轮结果与历史结果。
- 无法确认某项检查的实际输入或输出。
- 验证要求依赖当前不存在的可访问后端。

# 风险

- 历史 PASS 可能被误写成本轮验证结果。
- 没有运行中的后端，当前无法完成端到端复核。
- `note_id` 若不是跨运行稳定值，报告必须记录其有效范围。
- synthetic fixture 的通过结果不能推导真实知识库效果。
- 本地只读验证不能证明生产鉴权或长期公网暴露安全性。
- 普通 ChatGPT Web 的历史调用记录不能证明 GPT-Live 直接调用能力。
- 三份 fixture 的覆盖范围有限，不能代表真实用户检索效果。
