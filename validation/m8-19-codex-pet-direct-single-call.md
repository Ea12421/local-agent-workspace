老黄，以下是基于冻结事实编制的“staging 包合同回归审计”计划与判定报告。本轮仅形成审计方案，不执行检查、不读取文件、不访问网络、不修改任何内容。

## 1. 审计目标与明确不覆盖项

### 审计目标

验证 staging 包是否仍满足以下合同：

- 包含正确的 `pet.json` 与 `spritesheet.webp`。
- 元数据、图集尺寸、网格结构和有效格数量正确。
- 像素格式满足颜色、alpha、无抗锯齿等约束。
- 48×52 原生像素画和 192×208 整数倍预览规则满足要求。
- 视觉闸门满足角色、念珠、方便铲、轮廓、光照与逐帧一致性要求。
- 审计结果能够区分本轮实测、历史证据与尚未验证内容。

### 明确不覆盖项

本审计不覆盖：

- 安装、发布或写入 `~/.codex/pets`。
- 真实 Codex 运行效果或模型质量。
- Provider、ExecutionAgent 或订阅额度的重新验证。
- 账号、Cookie、Profile、秘密和无关项目。
- Web 或 Electron 容器的完整功能测试。
- 用户体验、性能、耗电和系统兼容性。
- 对历史图片、历史命令或历史日志进行重新读取。
- 任何未经确认的文件修改、依赖安装或服务启动。

## 2. 已知事实与历史证据

### 已知冻结事实

项目为 `codex-pet-studio`，项目状态标记为 `complete`。目标产品是可安装的原生像素风沙悟净 Codex 桌面宠物。

staging 合同要求：

- 原生绘制尺寸：48×52。
- 预览尺寸：只能是 192×208，即 4 倍整数倍 nearest-neighbor 放大。
- 官方图集尺寸：1536×1872，对应 8×9 网格。
- 有效格：57 个。
- 透明空格：15 个。
- 透明色之外最多 16 色。
- alpha 只能为 0 或 255。
- 禁止抗锯齿、渐变、柔光和半透明边缘。
- `pet.json` 必须包含：
  - `id=sha-wujing`
  - `displayName=沙悟净`
  - `spritesheetPath=spritesheet.webp`

视觉合同要求：

- 48×52 黑色剪影可辨认人物、念珠和方便铲。
- 像素簇连续。
- 不得是动漫大眼风格。
- 外轮廓清楚，但不能把全部内部细节画成粗黑线。
- 主光方向统一。
- 武器必须是细长直柄、浅弧月牙、短宽扇形铲。
- 武器不能像青龙偃月刀。
- 各帧不能出现逐帧结构漂移。

项目约束：

- 不读取秘密、账号、Cookie、Profile 或无关项目。
- 不安装新软件。
- 未经确认不写入 `~/.codex/pets`。
- 不发布。

### 已有历史证据

2026-09-27 曾有一次 Codex subscription 运行：

- 运行时长记录为 57548ms。
- `isMock=false`。
- 产生 9 个 provider events。
- 结构化 traceability 记录为 PASS。

既有离线 dry-run 记录曾宣称：

- 图集为 1536×1872。
- 有效格为 57 个。
- 透明空格为 15 个。

这些证据只作为背景，不等同于本轮验证结果。尤其不能据此宣称本轮 staging 包仍然满足合同。

## 3. 固定检查步骤

以下步骤应按顺序执行，且只针对 staging 包及其直接内容。

### 步骤一：确认审计对象和范围

检查内容：

- 确认 staging 包的实际路径和包内文件清单。
- 确认只检查 `pet.json`、`spritesheet.webp` 及审计所需的最小元数据。
- 确认没有访问秘密、账号、Cookie、Profile 或无关目录。

为什么检查：

如果审计对象不明确，后续尺寸和内容检查可能针对错误包，历史证据也无法与当前包建立对应关系。

验收条件：

- 明确唯一 staging 包。
- 包内至少存在 `pet.json` 和 `spritesheet.webp`。
- 未访问合同外的敏感或无关数据。

### 步骤二：检查 `pet.json` 合同字段

检查内容：

- 解析 `pet.json`。
- 检查 `id`、`displayName`、`spritesheetPath`。
- 检查 `spritesheetPath` 指向的文件确实位于同一 staging 包中。
- 检查 JSON 可被正常解析，且字段类型正确。

验收条件：

- `id` 精确等于 `sha-wujing`。
- `displayName` 精确等于 `沙悟净`。
- `spritesheetPath` 精确等于 `spritesheet.webp`。
- 引用文件存在且可读取。
- 任一必需字段错误或缺失，则该项 FAIL。

### 步骤三：检查图集尺寸与网格

检查内容：

- 读取 `spritesheet.webp` 的实际像素尺寸。
- 按 8×9 网格切分。
- 验证每格尺寸为 48×52。
- 验证总尺寸为 1536×1872。

验收条件：

- 图集尺寸精确为 1536×1872。
- 网格精确为 8 列×9 行。
- 每格精确为 48×52。
- 尺寸、网格或切分关系任一不符，则 FAIL。

### 步骤四：检查有效格和透明空格数量

检查内容：

- 对每个 48×52 格判断是否完全透明。
- 统计有效格与完全透明格。
- 保存每个格子的判定结果，避免只验证总数。

验收条件：

- 有效格精确为 57 个。
- 完全透明格精确为 15 个。
- 57+15 必须等于 72 个总格。
- 数量不符，或存在无法稳定判定的格子，则该结构合同 FAIL 或 PARTIAL，取决于是否能完成可靠计数。

### 步骤五：检查 alpha 与颜色上限

检查内容：

- 扫描所有像素的 alpha 值。
- 验证 alpha 只出现 0 和 255。
- 在排除透明像素后统计颜色数量。
- 明确颜色统计口径：按实际 RGBA/RGB 像素值统计，不把近似颜色合并。

验收条件：

- 不存在 0 和 255 之外的 alpha。
- 非透明颜色数量不超过 16 色。
- 任一半透明像素或颜色超过 16 色，则 FAIL。

### 步骤六：检查像素风完整性

检查内容：

- 检查是否存在抗锯齿产生的过渡色。
- 检查是否存在渐变、柔光或半透明边缘。
- 检查像素簇是否连续。
- 检查预览或派生图是否使用 nearest-neighbor 整数倍放大。

验收条件：

- 原图不存在半透明边缘、渐变或柔光。
- 预览尺寸如存在，必须精确为 192×208。
- 预览必须等价于原图每个像素复制为 4×4 区块。
- 使用非整数倍缩放、非 nearest-neighbor 或产生新颜色，均 FAIL。

### 步骤七：执行视觉闸门检查

检查内容：

逐格检查静态视觉，并横向比较所有有效帧：

- 黑色剪影是否能辨认人物。
- 念珠是否存在且结构稳定。
- 方便铲是否清楚可见。
- 画面是否避免动漫大眼。
- 外轮廓是否清晰。
- 内部细节是否没有全部粗化为黑线。
- 主光方向是否统一。
- 武器是否为细长直柄、浅弧月牙和短宽扇形铲。
- 武器是否误画成青龙偃月刀。
- 人物、念珠、武器和主要轮廓是否逐帧稳定。

验收条件：

- 所有硬性视觉禁项均不存在。
- 角色、念珠和方便铲在规定尺寸下可辨认。
- 武器结构符合合同，而非仅凭“看起来像武器”。
- 没有明显逐帧结构漂移。
- 无法通过图像检查确认时，不得自动视为 PASS，应标记为 PARTIAL 或 BLOCKED。

### 步骤八：建立本轮证据链

检查内容：

- 为每个检查项记录实际输入、检查方法、结果和证据位置。
- 将本轮结果与历史 dry-run、历史 subscription 记录分栏保存。
- 不把历史记录中的 PASS 复制为本轮 PASS。

验收条件：

- 每个合同项都有“本轮 PASS / FAIL / 未验证”状态。
- 历史证据明确标记为历史，不参与本轮实测结论。
- 任何只依赖历史记录的项目不得标记为本轮 PASS。

## 4. PASS、PARTIAL、FAIL 判定规则

### PASS

仅当同时满足以下条件时，整体审计才能判定 PASS：

- `pet.json` 字段全部正确。
- 图集尺寸、网格、有效格和透明空格数量全部正确。
- alpha、颜色数量和像素格式全部符合合同。
- nearest-neighbor 预览规则已得到本轮证据支持。
- 视觉闸门全部通过。
- 每个硬性合同项都有本轮可追溯证据。
- 没有依赖未复核的历史 PASS 代替当前验证。

### PARTIAL

出现以下情况之一时判定 PARTIAL：

- 结构检查有本轮证据，但视觉检查尚未执行。
- 视觉检查完成，但预览放大规则或像素往返一致性未验证。
- 某些项目只能由历史证据支持，本轮未重新检查。
- 审计对象或证据链部分可确认，但仍有合同项无法判定。
- 没有发现明确违反合同的证据，但也无法证明全部合同满足。

PARTIAL 不能用于发布、安装或宣称合同回归通过。

### FAIL

出现以下任一情况时判定 FAIL：

- 必需文件缺失。
- `pet.json` 的硬性字段错误。
- 图集尺寸或网格错误。
- 有效格、透明空格数量不符。
- 存在非法 alpha。
- 非透明颜色超过 16 色。
- 存在抗锯齿、渐变、柔光或半透明边缘。
- 预览不是 192×208 的 nearest-neighbor 4 倍放大。
- 视觉闸门中的硬性禁项出现。
- 武器明显变成青龙偃月刀形制。
- 帧间存在影响角色、念珠、武器或主要轮廓的结构漂移。
- 证据显示审计对象不是目标 staging 包。

## 5. 未知项与停止条件

### 当前未知项

本轮尚未确认：

- 当前 staging 包的实际位置和内容。
- 当前 `pet.json` 是否存在且字段正确。
- 当前 `spritesheet.webp` 是否存在。
- 当前图集尺寸、网格、有效格和透明空格数量。
- 当前颜色数量和 alpha 分布。
- 当前 WebP 是否保持像素无损往返。
- 当前预览是否为 192×208 的 nearest-neighbor 整数倍放大。
- 当前视觉表现是否满足角色、武器和逐帧稳定性要求。
- 历史证据是否对应当前 staging 包版本。

### 停止条件

审计必须立即停止并报告 BLOCKED，而不是猜测或扩大访问范围，当出现以下情况：

- 无法唯一确定 staging 包。
- 需要访问秘密、账号、Cookie、Profile 或无关项目。
- 需要安装工具或依赖。
- 需要启动服务、联网或发布。
- 需要写入 `~/.codex/pets`。
- 图像无法读取、格式损坏或无法可靠解析。
- 无法区分当前包与历史包。
- 视觉检查缺少可观察的 48×52 原生图像证据。
- 任一检查需要改变文件内容才能完成。

## 6. 风险与防止拔高结论的措施

主要风险：

- 用历史 dry-run 结果代替当前 staging 包验证。
- 只检查图像尺寸，遗漏颜色、alpha 或视觉禁项。
- 只检查单帧，遗漏逐帧结构漂移。
- 通过肉眼认为“像像素画”，但没有检查实际 alpha、颜色和缩放方式。
- 将 `isMock=false` 或 provider traceability PASS 错误解释为素材合同 PASS。
- 把“没有发现问题”拔高为“已通过全部合同”。
- 把视觉无法确认误报为 PASS。

防止措施：

- 所有结果使用“本轮实测”“历史证据”“未验证”三类标签。
- PASS 必须由当前 staging 包的逐项证据支持。
- 结构合同与视觉合同分别判定，任一未完成都不能整体 PASS。
- 视觉不确定时判定 PARTIAL，而不是凭印象通过。
- 历史记录只用于定位回归风险，不用于替代当前测试。
- 审计过程保持只读，不进行修复性修改。
- 任何范围外访问都触发停止条件。

## 7. 唯一下一步

在获得明确执行授权后，对唯一确定的 staging 包进行一次只读合同回归审计，按上述八个步骤逐项记录本轮证据，并最终输出唯一的 `PASS`、`PARTIAL`、`FAIL` 或 `BLOCKED` 结论。
